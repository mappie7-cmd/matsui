# 要件定義書

> `/spec` を実行すると、Claude が `docs/01_customer.md` を読んでここを埋めます。
> 埋まったら `/build` で実装します。

## 0. 画面の型

- **LAYOUT: `stage`** — 🔮 3行目「現在の受講状況と今後残りの講座内容が一目でわかる」は「どこまで進んだか」を表す言葉のため、段階（未受講／受講予定／受講済み）ごとに束ねる `stage` を選んだ
- **TONE: `indigo`** — 1行目の相手（中小企業診断士）は士業のため `indigo`
- **DENSITY: `roomy`** — 🔮 2行目「年間１カリキュラム（５〜７日程度）を４〜５年かけて」から、対象は年1回・少数の科目で、1件（1科目）が重い（多日程の研修）と推測し `roomy` を選んだ
- **UNIT: `科目`** — 🔮 診断士のカリキュラムは複数年にわたり「経営戦略」「財務会計」等の科目単位で構成されると推測し、数え方を「科目」とした
  → 確かめ方:「今のカリキュラムは、何という単位（科目名・テーマ名）で分かれていますか？」

## 1. このツールが解くこと

自分の受講状況（未受講／受講予定／受講済み）と、受講後の理解度が一覧で分かる。

## 2. 使う人と、使う場面

- 使う人: 新たに中小企業診断士に登録した鈴木さん
- 🔮 いつ開くか: 年1回のカリキュラム申込前や、研修を受けた直後に振り返るタイミング
  → 確かめ方:「このツールを開くとしたら、どんなタイミングで開きますか？」
- 開いて最初にしたいこと: 今年度、まだ受けていない科目が何かを確認する

## 3. 画面（1つだけ）

1. ステータスごとの件数バッジ（未受講 / 受講予定 / 受講済み の科目数）
2. 段階（未受講 → 受講予定 → 受講済み）ごとに束ねた科目一覧。各行に科目名・年度・理解度が並ぶ
3. 受講済みの科目には、自己申告の理解度（◎ / ○ / △）が表示される

## 4. データ項目

| 項目 | 型 | 必須 | 例 |
|---|---|---|---|
| 科目名 | 文字列 | ○ | 経営戦略論 |
| 年度 | 文字列 | ○ | 2年目（2027年度） |
| ステータス | 未受講 / 受講予定 / 受講済み | ○ | 受講予定 |
| 理解度 | ◎ / ○ / △ / 未評価 | - | ◎ |
| メモ | 文字列 | - | 復習：SWOT分析の型を再確認 |

## 5. 操作（3つまで）

| # | 操作 | 何が起きるか |
|---|---|---|
| 1 | 科目を追加する | 新規登録画面で科目名・年度・ステータスを入力すると、一覧の該当する段階に表示される |
| 2 | ステータスを進める（未受講→受講予定→受講済み） | 一覧上のボタンで段階が変わり、表示される束が移動する |
| 3 | 理解度を記録する | 受講済みにした科目に理解度（◎/○/△）を選ぶと保存される |

## 6. やらないこと

- 他の診断士の受講状況や理解度を共有・比較する機能（SNS的な機能）
- 協会・研修主催団体側の申込受付・出席管理機能
- AIによる理解度の自動採点・レコメンド機能
- ログイン・複数端末でのデータ同期（第3回で扱う）
- 決済・課金（第3回で扱う）

## 7. 完成条件

- [ ] 科目を追加すると、一覧の「未受講」の段階に表示される
- [ ] ステータスを「受講済み」に変えると、その段階に移動し理解度を入力できる
- [ ] リロードしても、追加した科目・ステータス・理解度が残っている

## 8. 保存方法

`localStorage` に1つのキーで保存する。キー名: `shindanshi-curriculum`

※ 端末ごとの保存です。複数人での共有は第3回で扱います。

## 9. ダミーデータ

初回表示用に3件（すべて架空の科目名）。
例: 「経営戦略論（1年目・受講済み・理解度◎）」「財務会計（1年目・受講済み・理解度○）」「店舗実習（2年目・受講予定）」
